# 全站英文适配计划（EN 模式零中文）— 实施与译文审校清单

- 日期：2026-09-28
- 目标：切到英文后，**全站任何可见文本、属性、meta/og、数据内容均无中文**
- 范围：29 个根页面 + `tt_game/` 子站 + `admin` / `draws-editor` / `404` / `umpire-training`
- 默认语言仍为 `zh`；EN 由右上角按钮切换，localStorage 键 `wfls-lang.v1` 不变

---

## 0. 策略回顾

不重写站点，扩展既有 i18n 模型：

| 层 | 做法 |
| --- | --- |
| 界面文案（按钮 / 表头 / 提示 / 错误） | `js/common.js` → `i18n.zh` / `i18n.en` + `data-i18n*` 属性 |
| 由 JS 拼出来的文案 | `i18n[currentLang].xxx` / `dcT(key, fallback)` / `gameT(key)` |
| 封闭枚举（赛事类型 / 赛季 / 标签 / 荣誉） | 词典 + `*_KEY_MAP` 查表，**只翻显示层** |
| 正文类内容（新闻 / 问答 / 赛事 / 简介 / 对阵表） | 数据文件里的 `_en` 同级字段 |

**绝不动数据规范键**：`类型` 取值、`胜者`/`负者` 字段名、`seasons.json` 的 `label`、`tags`/`honors` 数组值、颜色映射键、`tag` 白名单值。积分引擎、`ci_validate.py`、提交管线都按这些中文值联接，翻译只发生在 `eventTypeLabel()` / `wttEventTypeLabel()` / `seasonLabel()` / `playerTagLabel()` / `playerHonorLabel()` 的返回值上。

## 2. 工具：`tools/i18n_audit.py`

```bash
python tools/i18n_audit.py            # 全量报告（warn，不阻断 CI）
python tools/i18n_audit.py --html-only
python tools/i18n_audit.py --js-only
python tools/i18n_audit.py --data-only
python tools/i18n_audit.py --keys-only  # data-i18n* 引用的 key 是否存在、zh/en 是否对称
python tools/i18n_audit.py --strict     # 有残留退出码 1（稳定后并入 CI）
python tools/i18n_audit.py --json
```

四类检查：

1. **HTML** — `<body>` 内没有 `data-i18n*` 覆盖的含中文文本节点与可翻译属性。`data-i18n` 走 `innerHTML`，**祖先被覆盖即整棵子树被覆盖**。范围含根目录 `*.html` 与 `tt_game/*.html`。
2. **JS** — 用单趟词法器（认识行注释 / 块注释 / 三种引号 / 正则字面量 / 模板插值）提取字符串字面量。豁免：i18n 字典本体、`*_KEY_MAP` 自动抽取的数据键、挂了 `data-i18n*` 的模板串、`console.*`、`currentLang` 三元的语言分支。
3. **KEYS** — HTML 引用的每个 `data-i18n*` key 必须在 zh / en 两块里都存在，且两块的 key 集合对称。**这一类最值钱**：缺 key 时前端静默跳过，是纯浏览器才能发现的坑。
4. **DATA** — 内容条目缺 `_en` 同级字段。

> **已知局限**：静态扫描看不穿 `currentLang === 'en' ? A : B` 这类语言三元，也判断不了「本来就该保留的中文」（人名、数据键），因此 **JS 一栏会大量多报**（当前 523 条，实际浏览器里 0 条残留）。`--strict` 现在**不要**接进 CI。**权威检查是浏览器 EN 模式逐页巡检**（第 5 节）。

## 3. 数据内容层约定

| 文件 | 英文字段 |
| --- | --- |
| `data/{news,qa,competitions}/{id}/{id}.json` | `title_en` / `excerpt_en` / `content_en`（或 `contentFile_en` → `*.en.md`） |
| `data/about.json` | 每个 section 加 `title_en` / `content_en` |
| `data/changelog.json` | `title_en` / `changes_en`（数组，与 `changes` 等长同序） |
| `data/players.json` | `role_en` / `description_en`（**仅在中文源非空时**） |
| `data/draws.json` | `title_en` / `roundLabels_en` / 卡片 `player1_en` / `player2_en` / `note_en` |
| `data/umpire-quiz.json` | `meta_en` / `prompt_en` / `options[].label_en` / `explanation_en` |

**不加 `_en` 的**：`tag`（白名单键）、`tags` / `honors`（`ptag_*` / `phonor_*` 查表键）、`type` / `topic` / `id` / `uid` / `version`、`类型` 取值、`seasons.json` 的 `label`。

约定：

- `_en` 字段**可选**；缺失时英文模式回退中文（不会白屏），脚本 warn 提示漏译
- `content_en` 的 `{{media:N}}` 占位符必须与中文版**序号一一对应**，否则英文版丢图
- `_en` 参与版本快照：改译文 = 改内容，会归档新版本

## 7. 风险与约束

- **数据键不可翻**：`类型` 取值 / `胜者`/`负者` / `seasons.label` / 颜色 map 的中文键 —— 引擎、验证器、提交管线依赖，只做显示层映射
- **`data-i18n` 走 `innerHTML`**：注入 `_en` 内容前必须过 `escapeHtml`（正文 Markdown 走 `renderDetailBody` 现有转义路径）
- **默认语言仍为 zh**，EN 靠按钮切换，localStorage 键不变
- **新增 JS 渲染的视图必须注册 reapply 钩子**，否则切换语言需刷新才生效（钩子清单见 `AGENTS.md`）
- **新增内容条目要跑 `sync_content.py`**，并同步补 `_en`（漏了不会报错，但英文模式会回退中文）
