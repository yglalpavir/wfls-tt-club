# 阶段 1 实测结论：仿真胜率是假的，真正的瓶颈是仿真与实机的不一致

日期：2026-09-10
对象权重：`data/input-ai-extreme.json`（952 动作 / 128-192-128，`--eval-only` 不训练）

## 一句话结论

仓库里所有"胜率"都是仿真内数字，而仿真在 5 个地方与实机物理不一致。
逐个对齐后，**同一份权重、同一批种子**的仿真胜率从 74.4% / 73.2% 塌到 **31.4% / 29.8%**。
这 40+ 个百分点的差距不是模型变弱了，而是之前的仿真在**给模型记功它打不到的球**。

## 修掉的 5 处不一致（按影响排序）

| # | 不一致 | 旧仿真 | 实机 | 影响 |
|---|--------|--------|------|------|
| 1 | 触球判据 `swept` | 只要 `bz > plane - zF`（球过拍面前方就算） | `_prev.z<=plane+zF && bz>plane-zF`（本帧真实穿越） | 最大。仿真"几乎总能打到" |
| 2 | 发球过网高度 | `yC ≥ 网顶 + 1 球径` (0.9325) | `checkNet` 撞网带上限 `网顶 + 1.5 球径` (0.9475) | 22% 的发球在实机撞网 |
| 3 | 积分分辨率 | 单步 1/60 | 每帧 2 个 1/120 子步 | 轨迹系统性偏移，发球失误 |
| 4 | Magnus / 旋转衰减 | 解算器漏 z 分量、完全无 `s*=(1-0.05dt)` | 完整叉积 + 逐帧衰减 | 高旋长距离球完全没对齐 |
| 5 | 决策频率 | 60Hz 决策 | 15Hz（`frame%3`） | 训练里 16ms 可修正的错误，实机停留 50ms |

## 逐项实测数据

### #1 触球判据 —— 主因

修前（`tools/diag-reach.js --games 300`，对手 extreme-max）：
```
仿真胜率 59.3%    玩家输球原因：recv-out-recv:109  hit-floor:9  recv-out:4
```
即 **89% 的输球是"自己回球出界"** → 说明仿真里 DQN 几乎总是触球成功。

修后：
```
仿真胜率 41.0% →（叠加 #2/#3/#4 后）29.8%
玩家输球原因：recv-out-recv:168   hit-floor:0   recv-out:0
```

**实机对照**（`/api/ttstats` 遥测，修前样本）：判分 100% 是「对手未能回球」（根本没触球），
0 条「出界」。仿真与实机的输球构成**正好相反**——这就是 40 个百分点的来源。

顺带：`tools/diag-reach.js` 里的「必达对手」对照（moveSpeed/moveZ 拉满、moveErr=0，
等价实机 `aiMoveShared` 永远够得着）只差 0–2pp，所以仿真对手那 4 道 `reach:false` 硬门
不是主因（修 #1 前也只占 5–16% 的胜率）。

### #2 发球过网高度 —— 用 `tools/diag-serve-legal.js` 确定性证明

该脚本把 `serveShot` 的解用「实机同款积分器」（含 `checkNet` 判据）在 Node 里重放，
不依赖浏览器。500 个发球，出球点 y=0.9822（`strikeServe` 实际触发高度）：

```
修复前（旧阈值 0.9325）：两跳合法 390/500 = 78.0%   撞网 110 = 22.0%
修复后（新阈值 0.9625）：两跳合法 500/500 = 100.0%  撞网   0  =  0.0%
```

机制：`strikeServe` 的评分项 `netHigh = clamp(netY - netTop - 0.06, 0, 1)` **奖励贴网而过**，
旧 `netTop` 比实机撞网带上限低 0.5 个球径，于是解算器偏好"擦着网上限飞过"的发球，
实机 `checkNet` 一律判撞网并把球弹回己方 → `发球失误 · 两跳都在自己半台` / `发球出界`。

修前实机遥测：6 分对局里 3–4 分是发球失误（50–60%）。修后：3 分对局 0 次发球失误。

### #3 积分分辨率

`main.js:193` `const n = Math.max(1, Math.ceil(dt/(1/120)))` → 实机每帧 2 子步。
旧仿真 `DT = 1/60` 单步。`serveShot` 也按 1/60 解算，却在 1/120 的实机里跑。
现在：simcore 全部解算器共用 `SDT = 1/120`（循环步数同步翻倍保持时间覆盖），
`input-sim.js` 的 `playerReceive` 改为 `SUBN = 2` 子步。
效果：仿真里 `serve-net` 类失误完全消失。

### #4 Magnus z 分量 + 飞行中旋转衰减

旧 simcore 里 8 个 Magnus 应用点中，4 个只有 x/y 两个分量、**8 个全部没有**
`s *= (1-0.05dt)`；而实机 `physicsStep` 两者都有。现在全部对齐（`simcore.js` 8/8）。

### #5 决策频率

`constants.js` 单一 `DECIDE_SKIP = 3` → `SIM.C.DECIDE_SKIP` →
训练器 `playInputPoint(..., freq)` 与实机 `tt-player.js` 共用，启动断言防漂移。
单独影响（`/tmp/chk_skip.js`）：vs extreme 65.3% → 61.3%（-4.0pp），
每分决策数 50.9 → 17.4。

### 两个必须知道的新事实

1. **模型是弱模型，不是强模型。** 修完一致性后它对每一档都输约 2:1。
   之前 74% 的"极端对手胜率"是仿真记账错误。
2. **阶梯已经不区分难度了。** 五档全在 27–32%，非单调（default 反而最高）。
   继续按"逐级更强对手"训练，信号质量存疑——需要重新设计阶梯的区分度
   （见 `tools/diag-reach.js` 的 per-reason 分解，可以定位哪根难度轴真正生效）。

## 实机遥测

`js/tt-stats.js` + `/api/ttstats`（GET/POST）+ HUD chip，已在页内验证：
- chip 渲染 `DQN 2:4 (33.3%) · 1 触球 / 擦网 0% · 对手 extreme-max`
- 决策计数 `dec`、触球 `contacts`、动作分布 `txMean/txRange/myMean`、按原因分类的 `lostBy`
- 判分文案 `出界!` / `对手未能回球` / `发球出界` / `发球失误 · 两跳都在自己半台` 均可归类

样本量仍小（单局 3–11 分），**不能当胜率用**；它的价值是给出"触球数 / 撞网 / 出界 / 发球失误"
的构成，这是仿真里读不到的。

## 遗留问题

1. 实机仍有零星发球失误（6 分样本里 1 次），而 Node 确定性检验 500 发 0 失误。
   剩余差异最可能在 `strikeServe` 的实际出球点 x（由 DQN 当帧的拍位决定）与
   我在检验里取定的 x0 分布不完全一致。**待查**，不是训练阻塞项。
2. `physics.js` 的 `aiMoveShared` 对 AI 侧有磁吸（`canHit.ai && p.z<-magnetRangeZ`），
   仿真的 `aiReturn` 完全没有对手磁吸 → 实机 AI 对手比仿真对手更容易接球。
   这解释了"仿真说 DQN 自己回球出界、实机说 AI 回球出界"的方向差异。
   **待查**，是下一阶段 sim↔real 对齐的头号目标。
3. 训练侧触球条件 `bounced && v.z > 0.02`（`input-sim.js:183`）只允许弹跳后上升段，
   实机 `tryPlayerHit` 允许下降段拦截。已修 `swept`，但这条相位限制仍在。
