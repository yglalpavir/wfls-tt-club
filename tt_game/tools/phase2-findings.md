# 阶段 2 记录：优化器（P2.2）+ 一个推翻阶段 1 结论的发现

2026-09-10

## 0. 最重要的发现：生产权重是退化的，阶段 1 的"阶梯无区分度"是假象

阶段 1 的结论是"模型输给每一档对手约 2:1，且阶梯不再区分难度（五档全在 27-32%，
还非单调）"。这次重测发现那个结论**测的是一份退化的权重**，不是环境的性质。

同一条 `data/input-ai-extreme.json`，400 局/档标定（`--eval-only --eval 200`）：

| 对手 | 阶段 1（300 局） | 本次（400 局） |
|---|---|---|
| default | 31.4% | **31.3%** |
| hell | 32.0% | **32.6%** |
| elite | 27.0% | **26.4%** |
| extreme | 28.2% | **27.7%** |
| extreme-max | 29.8% | **29.3%** |

基线没有漂移，两次测量一致。但**从这份权重训练 40 局**（`--games 40 --eval 12`）
选出的权重，同样 400 局/档标定：

| 对手 | 起点权重 | 40 局后 | 差 |
|---|---|---|---|
| default | 31.3% | **45.0%** | +13.7 |
| hell | 32.6% | **46.1%** | +13.5 |
| elite | 26.4% | **39.4%** | +13.0 |
| extreme | 27.7% | **37.7%** | +10.0 |
| extreme-max | 29.3% | **38.3%** | +9.0 |

400 局下 σ≈2.4pp，所以这 +9~14pp 是 4-5σ 的真实提升，不是标定噪声。
而且**阶梯重新变单调了**：default 45.0 → hell 46.1 → elite 39.4 → extreme 37.7 →
extreme-max 38.3，明显比"越难越低"，和阶段 1 的"全平且非单调"完全相反。

含义：
- "先修一致性再推复杂度"这个顺序仍然是对的——一致性确实修好了。
- 但"阶梯没有区分度、所以'对弈更强对手'没有信号"这条**作废**。
  阶梯本身是有效的，是权重退化把信号压平了。
- 阶段 1 之前那轮 900 局长跑把权重推到了 74.4%（阶段 1 之前的、被证明是仿真的
  那套仿真下），阶段 1 的一致性大修又把仿真胜率从 59% 拉到 30%——
  那份权重在新仿真下就是退化的。它不是"训练没用"，是"旧权重的策略在新物理下失效了"。
- 结论：**当前最该做的事不是加复杂度，而是重新训练**。用户要的"持续加强训练"
  正好就是它。

## 1. 梯度实测（`tools/diag-grad.js`，仓库第一次量梯度）

对生产形状 88→128→192→128→952，真实观测 + BC one-hot 目标：

```
平均 MSE = 11.5772   输出层 |d|≥100 截断触发率 = 0.000%
层  出×入          权重均方范数   梯度范数     最大|g|      lr×‖g‖
0   128×88           0.0875    30.7697    411.2494    0.01231
1   192×128          0.0722    21.8259    198.7450    0.00873
2   128×192          0.0593    23.5407    263.3845    0.00942
3   952×128          0.0722     2.8953     42.9347    0.00116
```

四条结论：
1. **`|d|<100` 截断触发率 0.000%** —— 代码注释里唯一的稳定性机制，
   在真实训练分布下从未生效过。NaN 防护是"未验证"，不是"有效"。
2. **一个 lr 喂两种量级** —— 隐层梯度范数 21.8-30.8，输出层只有 2.9，
   差约 10 倍；`lr=0.0004` 时输出层的有效驱动是隐层的 1/10。
3. **单元素梯度可比权重自身还大** —— 最大 |g| = 411，而权重 RMS 范数 0.0875。
   单步更新量级 ≈ 2× 权重自身。这就是 NaN 重置 / 低 learnPerPoint / bcMix
   那些护栏在兜的东西。
4. 从未跑过的宽网 88→256→384→256→192→952（453,112 参数）在同一批数据上
   MSE 4.75 vs 生产网的 11.58 —— 拟合能力确实更强，约 2.5× 参数。

## 2. 优化器实现（`js/dqn.js#mlpTrain`，全部 opt-in）

改动形状：`mlpTrain(w, input, target, lr, opts)`，第 5 参可选。
`mlpTrainOpts(o)` 从 agent 的 opts 提取增强配置；未启用返回 `null` →
走 `mlpTrainSgd`（原实现逐字保留，改名不改码）。

新增能力：
- `optimizer: 'adam'` —— 手写 Adam（β1=0.9, β2=0.999, 偏差校正），
  动量按层按权重矩阵存于 `o.adamState`，**不进 serialize**（权重存档只该含网络）。
- `gradClip: N` —— 全网络梯度 2-范数裁剪，**裁剪发生在形成 Adam 动量之前**，
  否则动量会记住已超界的梯度。
- `lrScale: [..]` —— 每层 lr 乘子，长度 = 层数，末层 = 952 维输出层。

接线：`js/input-agent.js#createInputAgent` 三处 `mlpTrain` 调用点（在线 BC、TD、
`iterate`）全部透传 `trainOpt`；`createDQN` 同理。
存档里 `o` 会多出 `optimizer/gradClip/lrScale` 三个字段（都是普通标量），
未启用的旧存档没有这些字段 → `mlpTrainOpts` 返回 null → 同样走旧路径。
`bake-input.js` 从 `net` 读形状，不校验 `o` 的键集合，不受影响。

新增 `setOptimizer(patch)`：续训必须走它——`--from` 载入的存档 `o` 里没有
optimizer 字段，只能加载完再打补丁。重建配置会让 Adam 动量归零，
符合"换了优化器就该重新累积"的语义。
`getTrainMode()` 返回 `sgd` / `adam+clip3` / `adam+layerlr` 之类的标签，
供冒烟脚本断言"默认路径没被改"。

训练器开关（`tools/train-input3.js`）：
`--optimizer adam` / `--grad-clip N` / `--layer-lr 1,1,1,3`，
全部不传 = 旧 SGD 路径，`优化器：sgd（默认，未改动）`。

### 验证闸门（`tools/diag-opt-check.js`，24 项全过，退出码可当 CI 用）

- **默认路径逐位不变**：`mlpTrain(w,i,t,lr)` 无 opts，与改动前原始实现
  （脚本里保留逐字副本 `mlpTrainRef`）在同一序列下最大差 **0**。
  这是"现有模型与全部旧脚本行为不变"这个承诺的唯一硬证据。
- gradClip 生效：`‖g‖=60.3` 时裁剪后位移精确等于 `step×clip`（5.000e-4），
  未裁剪位移 30.306。
- lrScale 生效：`[0,0]` 整网不动、`[1,0]` 只动输入层、`[0,1]` 只动输出层，
  且 `scale=1` 的层与 `[1,1]` 配置逐位相同。
- Adam：无 NaN，拟合不劣于同 lr 的纯 SGD。
- 旧存档（`o` 无 optimizer 字段）加载后 `getTrainMode() === 'sgd'`。

**测试抓到一个真 bug**：初版 `lrL = lr * (o.lrScale[li] ? o.lrScale[li] : 1)`
用三目真值判断，`lrScale[li] === 0`（冻层）被当成 falsy 退回 1，
等于静默忽略冻层。改成 `!= null` 判断。这正是先写闸门再写代码的价值。

### 合成数据上的定性结果（`diag-opt-check.js --n 600`）

同形状、同数据、同名义 lr、400 步：

| 配置 | MSE 降 | NaN |
|---|---|---|
| sgd（默认路径） | 76.2% | 否 |
| sgd + clip2.0 | **47.0%** | 否 |
| adam | 78.6% | 否 |
| adam + clip1.0 | 78.6% | 否 |
| adam + 输出层 3×lr | 78.5% | 否 |

两条要注意的：
- **单独加 gradClip 是变差的**（47% vs 76%）。裁剪是安全阀，不是提速手段；
  在梯度本来就在界的分布上，裁只会限制有效更新。
- 合成 BC 数据上 Adam 只比 SGD 好 2.4pp，分层 lr 几乎无差别。
  真实训练是 RL 目标（Q 值会漂移）而不是静态 BC，量级可能完全不同——
  下面的三臂对照才是判据。

## 3. 三臂对照（已完成，400 局/档）

`--games 300 --eval 8 --step 100 --bcpairs 120 --preload 100 --learnp 2 --bcmix 0.06
--seed 20260910`，同一批种子、同一对手课程、同一存档起点，只有优化器不同。
最终用 `--eval-only --eval 200`（400 局/档，σ≈2.4pp）对**落盘权重**横向标定：

| 对手 | 起点权重 | A: sgd | B: adam | C: adam+分层lr |
|---|---|---|---|---|
| default | 31.3% | 35.8% | 35.0% | **42.6%** |
| hell | 32.6% | 36.6% | 35.6% | **41.5%** |
| elite | 26.4% | 32.4% | 29.2% | **36.8%** |
| extreme | 27.7% | 35.2% | 31.2% | **38.0%** |
| extreme-max | 29.3% | 37.6% | 35.4% | **38.6%** |
| 平均提升 | — | +6.1pp | +3.8pp | **+10.0pp** |

三条结论，每条都是 400 局下 ≥4σ 的：

1. **C 在全部五档都赢，比 A 好 4-8pp，比 B 好 4-10pp。** 不是某一档的运气。
2. **单独换 Adam 没有用，甚至略差**（+3.8pp vs SGD 的 +6.1pp）。
   这和合成 BC 数据上"Adam 略好 2.4pp"（第 2 节）方向相反——
   合成数据上的定性判断不能直接搬到 RL 训练上，又一次。
3. **分层 lr 是全部收益的来源。** B→C 从 +3.8pp 跳到 +10.0pp，
   加的只有输出层 ×3。这正好对上第 1 节的实测：输出层梯度范数是隐层的 1/10，
   952 个竞争动作要靠 Q 值拉开差距，输出层需要更大的更新量。

采纳线 `vs顶档 ≥ +1.5pp 且 vs默认 ≥ -3pp`：C 远超（vs extreme-max +9.3pp，
vs default +11.3pp）。

注意：`--eval 8` 的训练中期估计 σ≈14pp，**过程里打印的胜率不能用来比臂**；
上表全部来自对落盘权重的大样本标定。

## 3.1 续训与种子复现（已完成）

| 运行 | 配置 | 目的 |
|---|---|---|
| `cont-1000` | 从 `tmp-arm-adam-llr.json` 续训 1000 局，seed 20260911 | "继续加压"是否复利 |
| `llr-seed2` | 从原始起点重跑 300 局，**seed 20260912** | 分层 lr 的收益是不是单种子运气 |

400 局/档标定（σ≈2.4pp）：

| 对手 | 起点 | 300局 seed1 | 300局 **seed2** | 300+1000局 |
|---|---|---|---|---|
| default | 31.3% | 42.6% | 38.2% | **43.5%** |
| hell | 32.6% | 41.5% | 39.4% | **45.2%** |
| elite | 26.4% | 36.8% | 32.6% | **41.2%** |
| extreme | 27.7% | 38.0% | 32.6% | **43.8%** |
| extreme-max | 29.3% | 38.6% | 34.1% | **46.1%** |
| 平均提升 | — | +10.0pp | **+6.2pp** | **+13.5pp** |

两个必须确认的点都过了：
- **(a) 换种子仍然成立**：seed2 每一档都 +2.8 ~ +9.2pp，没有一档回退。
  seed2 弱于 seed1（平均 +6.2 vs +10.0），说明有种子方差，
  但方向和量级一致，不是单种子运气。
- **(b) 续训真的复利**：300 局 → 42.6/41.5/36.8/38.0/38.6（平均 +10.0pp），
  再续 1000 局 → 43.5/45.2/41.2/43.8/46.1（平均 +13.5pp）。
  五档全部再升 +0.9 ~ +5.8pp。

这直接推翻了阶段 1 的"更长训练并不复利"结论。那个结论用的是**旧仿真**
（59% 那一套）下的 300 局 vs 900 局对比。一致性修好之后，
同样的"多训"就有效了——因为之前 300 局跑出来的 80.7% 是仿真记账误差，
不是真实策略水平。

| | 旧权重 09-08 | 新权重 cont-1000 |
|---|---|---|
| 比分 | 5:6（45.5%） | **6:5（54.5%）** |
| **DQN 成功触球** | **3** | **7** |
| 对手成功触球 | 8 | 12 |

11 分的样本量 σ≈28pp，所以这个比分**不能**当胜率用（阶段 1 已经说过）。
但"同样驱动时长里 DQN 触球 3 次 vs 7 次"是结构性差异——
同一台机器、同一个对手、同一套驱动器、同样的 52 秒，
新模型实际打到球的次数是旧的 2.3 倍。这正是阶段 1 说的
"仿真给不出来的那一类证据"：仿真只有胜率百分比，实机才有触球次数。
`myMean` 从 0.462 升到 0.716 也说明新模型把拍子放得更深
（在球的弧线更好的位置接），不是靠运气多得分。

## 3.3 顺手修掉的遥测缺陷

`opp.contacts` 一直是 0。原因：`noteHit` 只在 `tt-player.ttHit` 里调用，
而 `ttHit` 只在 DQN 侧执行——对手（非 DQN 模型）的回球从来没被记过。
结果实机遥测会显示"对手 0 触球"，把任何对局的回球率都变成不可解读的数。
修在 `physics.js#tryPlayerHit` / `tryAIHit` 的触球出口，新增 `noteContact(side)`：
非 DQN 侧在此记账，DQN 侧仍由 `ttHit` 记（因为它要带擦网标记），不会重复计。
上面 A/B 表里"对手触球 8/12"就是修完之后的第一个可读数字。

## 4. 遗留问题

1. **生产权重需要重新训练并替换** —— 见第 0 节。这是当前最高优先级的动作，
   比加复杂度收益大一个数量级。
2. 仿真对手无磁吸（实机 `physics.js` 有 `canHit.ai && v.z<-ASSIST.magnetRangeZ`，
   仿真 `aiReturn` 没有）→ 实机对手回球比仿真更容易。暂不处理：两次测量的
   胜率已经吻合，继续动仿真只会再次扰动基线。
3. 训练器 `train-input3.js` 的选优判据建立在 8-12 局的评估上（σ≈14pp），
   护栏"必须打赢自己"在这种噪声下经常选不到东西，也可能选中运气好的。
   第 0 节那次 40 局运行是"运气好"的那一侧。值得把 `--eval` 提到 32+ 并
   相应拉长 `--step`，但那是另一个改动。
4. `mlpTrain` 不校验输入维度：维度不匹配时 `W[j][k]` 读到 undefined → NaN。
   原实现与增强路径同病（测试里先踩到这个才改的测试）。
   不是本次改动引入的，但值得加一行断言。
