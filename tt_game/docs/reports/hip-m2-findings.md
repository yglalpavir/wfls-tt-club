# HIP M2：战术意图层（L2）研究报告

> 承接 `hip-m1-findings.md`（L1 解析技能控制器）。
> 结论先行：**M2 在实机上把 vs 地狱 AI 的分点率从 70.7% 拉到 87.9%**（100 局口径见 §5），
> 远超 12 小时训练出来的输入级 DQN 锚点（60.0%）。
> 但最重要的产出不是这个数字，而是三个「真 bug」和一条机理结论：
> **在这个游戏里，为了控落点而挥拍 = 自杀**（§6）。

---

## 1. 目标

M1 的 L1 解析控制器证明了一件事：**在这个游戏的玩家侧，��数可解析的**——
预测落台点、把拍面放到正确的深度、用最小的挥拍把球稳定送回去，就能打到 70.7%（100 局），
而训练了 12 小时的输入级 DQN 只有 60.0%。

M1 剩下的问题也很清楚：**L1 只会「够得到」，不会「打得好」**——
它的落点是「交替往一边打 ±0.55」这种死规则，不知道对手在哪、不知道这一板该怎么调整。

M2 的目标：**加一层会打球的 L2**，但不能让 L2 把 L1 的「够得到」弄丢。

---

## 2. 架构

```
L0  物理层（simcore.resolveHit / physics.js）      —— 不许改
L1  解析技能层（js/hip-skill.js）                   —— 零学习参数，负责「够得到」
L2  战术意图层（js/hip-intent.js + js/hip-weights.js） —— 学习，负责「打得好」
L3  对手模型层（未实现）                             —— 未来：读对手的拍位/旋转来选战术
```

L2 的动作空间：**336 类意图** = 落点 7 × 深度 4 × 手法 6 × Ctrl 2，
网络结构 28 → 96 → 128 → 128 → **19 维（4 个头的 logits：7/4/6/2）**，
训练用 4 段独立的 softmax CE + label smoothing 0.03 + Adam + 全局梯度裁剪 2。

- 特征（28 维，`HIP_INTENT.features(obs)`）：球位/球速 8 + 预测接触点 4 + 速度 2 + 拍 4 +
  落台 2 + 对手拍位 x 1 + 旋转类型 1 + 是否弹起 1 + 自然落点 1 + 拍面目标深度 1 + 相对差 2。
- 深度 → 控制的映射：`my = sqrt((1.24 − depthZ) / 0.74)`（`my` 同时管出球深度 `aimZ = −1.24 + 0.74·my²`
  和弧线 `arcMouse = −0.28 + 0.58·my`）。

## 3. 教师与学生

### 3.1 教师（`tools/hip-teacher.js`）——搜索式打标

在 sim 里用 L1 打「有脑子」的球，每到出球决策点就枚举候选意图（约 110 个，掩码去重后），
对每个候选：

1. `SIM.resolveHit`（按该意图的 aim/my/ctrl 在**预测接触点**出球）
2. `SIM.simulateFull` 复核落点（出界/下网直接 −12 判死）
3. 打分：`2.4·pMiss + 1.2·qFar + 1.0·qDeep + 0.7·qSpeed − 1.6·risk`
   - `pMiss = sigmoid((到达时间 − 对手够到时间)/0.10)`：对手**够不到**的概率
   - `qFar`：落点离对手拍位的距离（打大角度）
   - `qDeep`：落点深度（1.05m 附近最佳）
   - `risk`：落点离台边的余量（贴边 = 出界风险）

标签按 4 个头**分头**做 softmax（temp 0.12），每个头在自己的边际最优分数上归一化。

数据：`data/hip/teacher-v2.ndjson`，4500 样本 / 57s 生成，教师自胜 8048/9000 ≈ 89%。

> v1 的标签是 336 路单头softmax，最大概率只有 0.026（几乎是均匀分布），
> 拿它训练学生等于在拟合噪声 ⇒ 必须分头 + 边际最优。

### 3.2 学生（`tools/hip-train.js`）——4 头 CE 蒸馏

teacher-v2 训练 30 epoch（31s）后的验证集 top1：

| 头 | top1 | 说明 |
|---|---|---|
| place（落点） | 94.8% | 学得很好 |
| depth（深度） | 76.1% | 可用 |
| stroke（手法） | 33.7% | 弱（教师标签本身 drive/block 经常并列） |
| ctrl | 100% | 恒为 0（教师从不搓球） |
| 组合（336 路） | 25.7% | = 94.8%×76.1%×33.7% |

## 4. 三个真 bug（M2 最花时间的地方全是接线，不是算法）

### 4.1 第三道闸门写在 `else` 分支里 ⇒ 对意图路径**从来没生效过**

```js
if(intent){ /* 第二道闸门 */ } else {
  ...
  /* ★ 第三道闸门 */ if(intent && cfg.intentVerify && ...) { ... }   // ← 永远到不了
}
```

「合法性闸门」（触球前用 `resolveHit + simulateFull` 复核落点，出界就丢弃意图）
写在了「没有意图」的分支里。**三道闸门实际只落了两道。**
修法：把闸门块移到 `if/else` 之后。修复后实机 62.5% → **73.2%**（40 局）。

### 4.2 `fromHeads` 收到的是数字而不是四个下标 ⇒ 意图恒为 id 0

`HIP_INTENT.fromHeads(sel)` 期望 `sel = [place, depth, stroke, ctrl]`，
但接线写的是：

```js
const sel = HIP_INTENT.argmax(HIP_WEIGHTS, feats);   // ← 19 维里的**全局** argmax（一个数字）
const id  = HIP_INTENT.fromHeads(sel);                // ← 数字当数组用
```

`sel[0]` 是 `undefined` → `undefined|0 = 0` ⇒ place/depth/stroke **全部退化成 0**，
意图永远是 id 0（落点 −0.62、深度 0.45、drive）。

⇒ **学生从头到尾没有真正参与过决策**。实测到的「意图层效果」全是闸门的效果。

修法：新增 `HIP_INTENT.argmaxHeads(weights, feats)`（逐头取最大值，返回长度 4 的数组）
和 `HIP_INTENT.decide(weights, feats)`（一步到位），三处调用点
（`js/tt-player.js`、`tools/hip-sim.js`、`tools/live-match.js`）统一改用 `decide`。

> 教训：多头模型的 argmax **必须逐头取**。19 维的全局 argmax 和 4 个头的 argmax
> 在数值上完全不同，而且这种 bug 不会报错，只会让模型退化成常量策略。

### 4.3 闸门把「深度」信号整个抹掉了

第二道闸门把意图给的 `my` 夹进实机验证过的安全带 [0.50, 0.58]，
而学生的 depth 头输出映射过来是 {0.23, 0.63, 0.85, 1.03} ⇒ **100% 被夹到边界**（0.50 或 0.58），
深度头等于没有。更糟的是这条安全带是**在 L1 路径上测的**，
那时 `my` 同时管拍面深度和出球深度；pz 通道上线后意图路径的 `my` 只管出球深度，
安全带必须重测（§5.2）。

## 6. 机理结论（这次研究最有价值的部分）

### 6.1 为了控落点而挥拍 = 自杀

玩家侧的落点公式是

```
aimX = 0.55 · 拍位x + 0.30 · 拍速x
```

拍位被接触窗口锁在球附近（±0.14m），所以**落点几乎只能靠挥拍（拍速）来变**。
但挥拍命令 `tx = px + hold + vCmd/PACE` 会让拍子在触球前漂移 `≈ 0.065 · vCmd`：

- L1 默认 want = ±0.55 ⇒ 必须挥到 vCmd ≈ 2 ⇒ 漂移 ≈ 0.13m ≈ 整个接触窗口 ⇒ **够不到**
- 意图层 want = 自然落点 ± 0.30 ⇒ vCmd ≤ 0.8 ⇒ 漂移 ≤ 0.05m ⇒ **够得到**

**同样的球、同样深的落点，只因为挥拍幅度不同，胜率差 17pp。**

### 6.2 「拍面深度」必须与「出球深度」解耦

`my` 在 L1 路径里同时干两件事：出球深度/弧线（`aimZ`/`arcMouse`）**和**拍面深度
（`tz = 0.92 + 0.8·my`，进而影响触球高度 → `arcFit` → 弧线 → 落点深度）。
两件事耦合在一起时，任一个旋钮都会连带改三个物理量，调参空间极窄。
pz 通道（拍面深度独立通道，`hip-skill.js` + `tt-player.js` + `input-sim.js`）把两者拆开后，
`my` 变成一个纯粹的「出球深度/弧线」旋钮，安全带才有可能被找到（§5.2）。

### 6.3 在这个游戏里，选手能控制的其实很少

- **落点 x**：≈ 0.55·球x（拍子必须在球旁边）⇒ 真正能调的是 ±0.15~0.30，代价是挥拍风险
- **落点深度**：my（窄带，尖峰 0.54）
- **球速/弧线**：pz（拍面深度涌现的 fwd）+ 旋转类型
- **搓球**：ctrl（只在下来旋时可用）

⇒ 战术空间的真实维度大约 **3~4 维**，而不是 336 类。

## 7. 失败实验清单

| 实验 | 结果 | 结论 |
|---|---|---|
| 336 类单头 softmax CE（teacher-v1） | 验证 top1 16.9%（噪声级） | 标签太软，必须分头 + 边际最优 |
| 硬目标 BC / MSE（1904 维，DQN 时代） | qmax 1e86~1e93 | 输出维度大 ⇒ 必须用分类/排序损失 |
| 意图给绝对落点（球 +0.3 → 落点 −0.62） | 100% 够不到 | 落点闸门（±0.30）必须存在 |
| 深度闸门 [0.50,0.58]（用 L1 路径测的带） | 深度信号被完全抹平 | 安全带必须在**当前路径**上重测 |
| 合法性闸门提前到 tau<0.12 + 台面余量 0.05 | 73.2% → 65.0% | 闸门太早 ⇒ 拍子被拽离球；太严 ⇒ 频繁回落 |
| `maxSwing` 2.0 → 0.8 | L1 70.7% → 69.6%（无伤） | 挥拍上限必须压小，否则落点调整必然牺牲够球率 |

## 8. 下一步

1. **每球锁存（L2 决策的一致性）**：现在 L2 每帧（60Hz）重新决策，
   落点目标在球飞行途中会变，拍子被来回拽。需要像 `serveLock` 一样**每球只决策一次**。
2. **动作空间收缩到「已验证安全的 K 个选项」**（K ≈ 6~9）：
   每个选项 = 一个实机验证过的 (my, 挥拍幅度, ctrl) 组合，
   学生只做分类，不再直接给连续量 —— 这比 336 类稳得多，也不会有「出界」这种不可挽回的错误。
3. **重训教师**：教师打分里的 `pMiss` 用的是「对手匀速跑到位」的近似，
   换成 `input-sim.aiReceive` 的真实对手 rollout（能算对手的实际失误率）。
4. **L3 对手模型**：obs 里已经有对手拍位 x（`ox`），下一步加对手的站位偏好/旋转倾向，
   让 L2 能做「针对这个对手」的落点选择。
