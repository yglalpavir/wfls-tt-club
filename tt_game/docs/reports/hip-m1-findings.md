## 2. M1 的设计（`js/hip-skill.js`）

**L1 解析技能控制器**：输入与训练侧完全同构的 15 字段 obs，输出 `{tx, my, ctrl}`
——与真人玩家的输入完全同口径，所以训练侧（`input-sim` 的 `brain.act`）与实机
（`tt-player.ttTick`）可以共用同一条物理管线。

```
来球上升沿 → 预测接触点（SIM.predictMeetZ + 线性外推到拍面所在 z 平面）
           → 追位（位置律：tx 直接指向预测接触点，早到位、早停）
           → 触球前挥拍阶段：落点闭环（把「拍位+拍速」这条直线拉到目标落点）
           → 手法选择（下旋搓 / 挑 / 常规，按来球旋转与高度）
```

关键公式（全部来自现有代码，未改物理）：

- 落点：`aimX = AIM.xFromPos·拍位x + AIM.xFromSwipe·拍速x`（0.55 / 0.30）
- 落点深度：`aimZ = −1.24 + 0.74·my²`
- 前冲：`fwd = fwdOf(pad.svz)`（由追位动力学涌现，玩家侧无法直接指定）
- 接触窗口：`SIM.fitWindow(stance, relTop, ballY, v, s, allowPush)`

## 3. 实施过程中踩到的四个真 bug（都属于「想当然」，不是物理问题）

### 3.1 接触点预测只在来球第一帧算一次 → 追位律失效（分点率 0%）

追位律是「时间归一」纯追踪律 `dpx/dt = (bx − px)/tau`：**tau 必须收缩**，拍面才会
收敛到接触点。早先只在上升沿算一次 tau（0.42s 恒定），追位律退化成「朝一个
固定点匀速走」，球拍到位时球早走了 → 100% 够不到（`lose:out` 全部）。
改成**每帧重算**接触点后，分点率 0% → 20%。

### 3.2 落点目标在上升沿锁死方向 → 纠偏反向，把拍子从球上拽开（够不到 92%）

上升沿那一帧球还在半路，预测还远（球带侧旋会拐弯，实测预测 bx=−0.74 而
「期望落点侧」锁成了 +0.46）。于是触球前 0.1s 的落点纠偏往**反方向**拉，
`tx` 从 −0.74 跳到 −0.58，拍子直接离开球 → 92% 的球变成「够不到」。
改成**方向每帧跟随当前预测**（只有「中球变线用哪一侧」整板锁定）后恢复。

### 3.3 追位用速度前馈 → 到位时拍速仍是 1~2 m/s → 落点顶到台边出界（23% 出界）

`tx = px + (bx−px)/(tau·PACE)` 在连续极限下等价于「以恒定速度 C=d0/tau0 移动、
恰好在触球时刻到位」，于是**到位时拍速还是 C**。而落点公式里拍速占 0.30 的权重：
宽球 bx=0.6、拍速 1.5 时 `aimX = 0.55·0.6+0.30·1.5 = 0.78`（被夹到 0.62），
落点 x 顶到 ±0.75/±0.76（台边 0.7625）→ **23% 的球直接飞出边线**。
改成**位置律**（`tx` 直接指向预测接触点，早到位、早停）后：到位拍速 ≈ 0，
落点回到 0.55·bx ≈ 0.33，稳稳在台内，出界率 23% → 0%。

### 3.4 仿真里「分点率」是饱和指标，坐标下降会收敛到「拖时间」

烘焙 DQN 在同一仿真下分点率 **97.1%**，但**平均每分 471 板**（撞 500 板上限判负）
—— 仿真里谁都不主动结束一分，比分毫无意义。
① 目标函数改成「在 maxShots 板内结束的一分里赢多少」，**平局计入分母**；
② 早期版本漏算平局 → 分母只有胜场，一个「永远打不完」的策略显示 100%
（实测 `myDrive=0.54` 时 581 分全是平局、154 胜 → 显示 100%）。
修正后同一目标函数下坐标下降给出的旋钮在实机只有 57.9%（仿真 88%），
**再次印证「仿真只能排序、实机才能判定」**。

⇒ 与 DQN 锚点**基本持平**，其中 default 档更好。

从假设变成了实测结论（下面的 §5 给出精确原因）。

### 旋钮敏感性（实机 60 局/点，`myDrive`）

| myDrive | 实机分点率 | 失分：够不到 / 自己出界 |
|---|---|---|
| 0.38 | 4.3% | 88 / **204** |
| 0.46 | 12.7% | 88 / **152** |
| **0.54** | **57.9%** | 69 / 19 |
| 0.62 | 56.2% | 59 / 29 |

`my` 同时决定拍面深度（`effZ = 0.92+0.8·my+(meetZ−1.32)·fitW`）与出球深度
（`aimZ = −1.24+0.74·my²`），实机在 0.46→0.54 之间有一个**陡峭的悬崖**：
浅拍位 → 触球点低、弧线平、落点压到台边 → 大面积出界。

## 5. 根因定位（`--hip-probe`：直接包裹实机 `tryPlayerHit` 逐帧记判据）

实机接触判据（`js/physics.js#tryPlayerHit`）：

```js
if(lastHitter==='player' || !canHit.player) return;         // 闸门
const W = SIM.fitWindow(stance, relTop(), ball.pos.y, ball.vel, ball.spin, !!ctrlHold);
const swept = (_prev.z<=plane+zF && ball.pos.z>plane-zF && ball.vel.z>0);
const prox  = Math.abs(ball.pos.z-g.z)<PAD_HD+BALL_R*2+zF && ball.vel.z>-0.3;
if(!(swept||prox)) return;
if(Math.abs(ball.pos.x-g.x)>PAD_HW+BALL_R+fitH) return;      // ← 真正的卡点
if(Math.abs(ball.pos.y-g.y)>PAD_HH+BALL_R+fitV) return;
```

20 局实测（n=2845 次判据调用，341 次放行）：

| 量 | p50 | 阈值 | 结论 |
|---|---|---|---|
| 落点差 \|球x−拍x\| | 0.078 | ±0.140 | 大部分够得着 |
| 纵向差 \|球y−拍y\| | 0.089 | ±0.175 | 够得着（y 超限仅 61 帧） |
| 触球高度 | **0.820** | 高球阈值 0.89 | **全是低球** |
| 闸门 `canHit` | true 399 / false 40 | — | 只挡 9% |

**关键：`fitH` 只在球高 > `TABLE_TOP+0.13 = 0.89` 时才放宽**
（0.026 → 0.21，即横向容忍 0.146 → 0.33m）。而实机触球高度 p50 = 0.82，
**永远吃最窄的窗口**；「够不到」的那些球，横向差 ~0.15m —— **差 1~2 厘米被拒**。

### 试过但失败的解法

把拍位做浅（`myApproach=0.34`）→ 触球点更高 → 窗口放宽到 ±0.33m：
够不到 78% → 41% ✓，但 `my` 同时决定出球深度，浅 `my` 让落点压到台边
→「自己出界」24% → 59% ✗，分点率反降到 8%~27%。
**根因**：`my` 的两副用途无法解耦 —— 接触帧比预测触球时刻早 1~3 帧
（`prox` 允许球还差 0.09m 就碰），「触球前切回出球深度」经常来不及。

⇒ **M2 的第一优先任务不是学策略，而是让「触球时刻」可控**：
要么把「拍面深度」与「出球深度」解耦（需要改 `tt-player`/游戏侧，但**不改物理判据**），
要么把控制器的 `my` 语义从「一个旋钮」拆成「拍面深度 / 出球深度」两个通道。

## 7. 下一个里程碑（M2）的建议顺序

1. **拆 `my` 的两副用途**（拍面深度 / 出球深度），或让「触球时刻」可预测
   —— 这是 M1 剩下的唯一硬瓶颈（够不到 82.6%）。
2. 接触点预测的剩余误差：实机探针显示预测误差 p50 0.05m（但该数字被
   「穿越帧与触球帧差一帧」污染，实际更小），值得再单独量一次。
3. 然后才轮到 L2 战术策略（336 类意图）+ 搜索教师 + CE 蒸馏。
   L1 把「够得到」做到及格后，L2 的边际收益才看得清。
