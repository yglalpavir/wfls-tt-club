## 2. M1 的设计（`js/hip-skill.js`）

**L1 解析技能控制器**：输入与训练侧完全同构的 15 字段 obs，输出 `{tx, my, ctrl}`
——与真人玩家的输入完全同口径，所以训练侧（`input-sim` 的 `brain.act`）与实机
（`tt-player.ttTick`）可以共用同一条物理管线。

```
来球上升沿 → 预测接触点（SIM.predictMeetZ + 线性外推到拍面所在 z 平面）
           → 追位（位置律：tx 直接指向预测接触点，早到位、早停）
           → 触球前挥拍阶段：落点闭环（把「拍位+拍速」这条直线拉到目标落点）
           → 手法选择（下旋搓 / 挑 / 常规，按来球旋转与高度）
```

关键公式（全部来自现有代码，未改物理）：

- 落点：`aimX = AIM.xFromPos·拍位x + AIM.xFromSwipe·拍速x`（0.55 / 0.30）
- 落点深度：`aimZ = −1.24 + 0.74·my²`
- 前冲：`fwd = fwdOf(pad.svz)`（由追位动力学涌现，玩家侧无法直接指定）
- 接触窗口：`SIM.fitWindow(stance, relTop, ballY, v, s, allowPush)`

## 3. 实施过程中踩到的四个真 bug（都属于「想当然」，不是物理问题）

### 3.1 接触点预测只在来球第一帧算一次 → 追位律失效（分点率 0%）

追位律是「时间归一」纯追踪律 `dpx/dt = (bx − px)/tau`：**tau 必须收缩**，拍面才会
收敛到接触点。早先只在上升沿算一次 tau（0.42s 恒定），追位律退化成「朝一个
固定点匀速走」，球拍到位时球早走了 → 100% 够不到（`lose:out` 全部）。
改成**每帧重算**接触点后，分点率 0% → 20%。

### 3.2 落点目标在上升沿锁死方向 → 纠偏反向，把拍子从球上拽开（够不到 92%）

上升沿那一帧球还在半路，预测还远（球带侧旋会拐弯，实测预测 bx=−0.74 而
「期望落点侧」锁成了 +0.46）。于是触球前 0.1s 的落点纠偏往**反方向**拉，
`tx` 从 −0.74 跳到 −0.58，拍子直接离开球 → 92% 的球变成「够不到」。
改成**方向每帧跟随当前预测**（只有「中球变线用哪一侧」整板锁定）后恢复。

### 3.3 追位用速度前馈 → 到位时拍速仍是 1~2 m/s → 落点顶到台边出界（23% 出界）

`tx = px + (bx−px)/(tau·PACE)` 在连续极限下等价于「以恒定速度 C=d0/tau0 移动、
恰好在触球时刻到位」，于是**到位时拍速还是 C**。而落点公式里拍速占 0.30 的权重：
宽球 bx=0.6、拍速 1.5 时 `aimX = 0.55·0.6+0.30·1.5 = 0.78`（被夹到 0.62），
落点 x 顶到 ±0.75/±0.76（台边 0.7625）→ **23% 的球直接飞出边线**。
改成**位置律**（`tx` 直接指向预测接触点，早到位、早停）后：到位拍速 ≈ 0，
落点回到 0.55·bx ≈ 0.33，稳稳在台内，出界率 23% → 0%。

### 3.4 仿真里「分点率」是饱和指标，坐标下降会收敛到「拖时间」

烘焙 DQN 在同一仿真下分点率 **97.1%**，但**平均每分 471 板**（撞 500 板上限判负）
—— 仿真里谁都不主动结束一分，比分毫无意义。
① 目标函数改成「在 maxShots 板内结束的一分里赢多少」，**平局计入分母**；
② 早期版本漏算平局 → 分母只有胜场，一个「永远打不完」的策略显示 100%
（实测 `myDrive=0.54` 时 581 分全是平局、154 胜 → 显示 100%）。
修正后同一目标函数下坐标下降给出的旋钮在实机只有 57.9%（仿真 88%），
**再次印证「仿真只能排序、实机才能判定」**。

## 4. 实机成绩（`tools/hip-eval.js`，seed 20261004，**100 局/档**）

| 对手 | HIP-L1（解析技能层） | DQN 锚点（ckpt-000500，30 局） | Δ |
|---|---|---|---|
| **hell** | **70.7%** [65.1, 75.7] | 60.0% | **+10.7pp** ✅ M1 门槛 ≥70% 达成 |
| default | 88.5% [85.4, 91.0] | 92.1% | −3.6pp（锚点只有 30 局，CI 很宽） |
| grandslam | 88.8% [85.9, 91.3] | 91.0% | −2.2pp（同上） |

失分原因分解（跨 3 档 200 分）：

| | HIP-L1 | DQN（锚点） |
|---|---|---|
| 够不到（未能回球 + 双跳） | 99.0% | ~71.5% |
| **自己出界 / 下网** | **1.0%** | ~25% |

**结论：HIP-L1 用零学习参数，在最强对手（地狱 AI）上超过训练 12 小时的 DQN +10.7pp，
且「自己打出去」几乎消失（25% → 1%）。** 剩下的失分几乎全是「够不到」——
这正是 M2（意图策略层 + 对手模型）要攻的方向。

> Node vm 驱动 60Hz）。仿真侧只用来**排序候选**——实测仿真里烘焙 DQN 是 97.1%
> 但平均每分 471 板（撞 500 板上限），完全饱和，毫无参考价值。

## 5. 第五个真 bug：预测器与实机的「弹跳判据」不一致 ★ 决定性

前面四个 bug 都是**控制律**问题（追位律、落点闭环、拍面深度耦合）。最后一个不是：
它让控制器**根本不知道球会落在哪**。

### 5.1 症状

`--hip-probe` 逐帧包裹实机 `tryPlayerHit`（真实判据，不是复刻），20 局 2996 次调用：

* 「球已到拍面深度」的决定性帧 396 个：放行 372，**横向 x 超限 0**，**纵向 y 超限 24**；
* y 超限帧的**球高 p50 = 0.581**（0.386~0.705）—— 球还在**台面以下**（台面 0.76），
  即球越过拍面深度时**还没落地弹起**，直接从拍下穿过；
* 漏球帧 **24/24 没有落台预测**（`hasMeet=false`），成功帧 372/372 都有。

### 5.2 根因

控制器用 `SIM.predictMeetZ` 预测落台点，而它的弹跳判据与实机**不一样**：

```
实机 physics.js:340-341
  v.y<0 && p.y-BALL_R<=TABLE_TOP && _prev.y-BALL_R>TABLE_TOP-0.05
  && |p.x|<=TABLE_W/2+BALL_R*0.6 && |p.z|<=TABLE_L/2+BALL_R*0.6

simcore.predictMeetZ
  v.y<0 && p.y-BALL_R<=TABLE_TOP && |p.x|<=TABLE_W/2 && |p.z|<=TABLE_L/2
```

差三处，每一处都致命：

1. **台面外沿**：实机多 0.6·BALL_R = 1.2cm。落台点 z ∈ [1.370, 1.382] 的球
   **实机会弹起、预测器不认** ⇒ 这批球整个被预测漏掉 ⇒ 拍面深度失去依据 ⇒ 球从拍下穿过。
2. **上一子步条件**：实机要求球在上一子步还在台面之上，陡降的球实机**不弹**；
   预测器会弹。
3. **z 窗口下界**：`predictMeetZ` 找的是「弹起后第一次进入 y 窗口且 z ∈ [zLo,zHi] 的点」，
   而 zLo 默认 0.92 = 玩家半台内沿。落台点若在 z < 0.92（短球/擦网球），
   球从此单调向 +z 走，**永远进不了窗口** ⇒ 函数一路积分到球落地才返回 null。

### 5.3 修法

`hip-skill.js#predictContact` 重写为**逐子步照抄实机**的积分器
（1/120 子步、同一套重力/阻力/Magnus(s×v)/旋转衰减/弹跳判据/`tableBounce` 公式），
并一路跟到「球到达拍面深度」的那一点，返回：落台点 z、落台时刻、落台后 vz、
**拍面目标 z**（= 落台点 z + `padZOffset`）。同时把 z 窗口下界放宽到 0.15。

**效果：68.2% → 73.6%（40 局）→ 正式验收 70.7%（100 局，CI 下界 65.1%）。**

> 教训（与仓库里已有的一致）：**训练/仿真侧的物理常数与实机只要有一处判据不同，
> 就会变成「模型够不到球」这种看起来像策略问题、其实是口径问题的故障。**
> 之前 phase5 的「71.5% 够不到」和这次的「24/24 无落台预测」是同一类病。

## 7. 失败实验清单（都已回退，默认关或回默认值）

| 尝试 | 实机结果 | 否决理由 |
|---|---|---|
| 速度前馈追位律 `tx = px + (bx−px)/(τ·PACE)` | 分点率 0%（全部 lose:out） | 连续极限下等价「以恒定速度 C=d0/τ0 移动并恰好到位」⇒ **到位时拍速仍是 C**；落点公式里拍速占 0.30 权重 ⇒ 宽球 aim 被顶到台边出界 |

## 8. 下一步：M2（意图策略层）

M1 之后剩下的失分 **99% 是「够不到」**。够不到有三种来源，M2 逐一对应：

1. **反应时间**：球在对手击球瞬间才进入预测视野 → 需要「对手模型」提前站位
   （AI 落点永远在玩家反侧 ⇒ 可用最近 N 板估计它的落点偏好）。
2. **落点覆盖**：球在台面深处（落台 z > 1.0）时，弹起后到拍面深度只有 2~3 帧，
   拍面必须**提前**到位 → 需要按落台深度分级处理。
3. **战术**：知道对手在哪，就该往**反侧**打 → 这才是 L2 该学的。

M2 交付物（不变）：

| 文件 | 内容 |
|---|---|
| `tt_game/js/hip-intent.js` | 336 类意图空间（落点 7 × 深度 4 × 打击 6 × Ctrl 2）+ 掩码 + `intentToControls`（意图 → L1 控制量的反解） |
| `tt_game/tools/hip-teacher.js` | 短程 rollout 搜索教师：对每个状态枚举候选意图，用 `SIM.simulateFull` + 对手 `aiReceive` 采样打分，产出 soft label |
| `tt_game/tools/hip-train.js` | CE 蒸馏（softmax + label smoothing），产出 `js/hip-weights.js`（约 0.1~0.5MB） |
| 联赛 / PFSP | 对手池 = 脚本阶梯 + 历史快照 + nemesis + 人类拟合模型 |

L1 接口改造（M2 前置）：`plan(obs, intent)` —— 意图给出「期望落点 x / 深度 / 打击 / Ctrl」，
L1 负责把它解成 {tx, my, ctrl, pz}。当前 L1 内部的落点目标（`S.want`）就是
「意图」的一个特例，改造时保持默认行为不变。
