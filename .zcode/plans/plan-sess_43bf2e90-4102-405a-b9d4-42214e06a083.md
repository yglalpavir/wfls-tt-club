# 导出个人数据（战绩卡图片）+ 导出 n/c/q 为图片 — 实施计划

## 背景结论（已探明）
- 站内已有导出基础设施：`js/common.js:406-599` 纯 Canvas 手绘排行表导出（跟随明暗主题），配套 `_rankImgDataUrlToBlob` / `_downloadRankImageBlob` / `buildExportFileName`，可直接复用。
- n/c/q 内容含 KaTeX 公式、表格、加粗（q2、c6、n17/n18），纯手绘无法还原 → 详情导出走 **html2canvas 1.4.1 DOM 截图**（cdnjs + SRI 校验，与站内 Chart.js/marked 加载方式一致）。`style.css` 的 `color-mix()` 只出现在 wtt-egg 规则（仅 WTT 页使用），detail/player 页可安全使用 html2canvas。
- 个人数据页 = `player.html?uid=x`（personal_stats.html 点击球员即跳转过去）。

## A. 共享基础设施（js/common.js）
新增 `exportDomNodeAsImage(node, opts)`（放在现有导出函数旁）：await `document.fonts.ready` → `html2canvas(node, {scale: 2~3·DPR, backgroundColor: null, useCORS: true, logging: false})` → 复用现有 blob/下载/文件名工具；try/catch → 提示失败文案。
i18n（zh/en 各加）：`img_export_fail`（图片导出失败，请重试 / Image export failed. Please try again.）、`export_gen`（生成于 / Generated）。

## B. 个人数据 → 战绩卡图片（player.html，纯 Canvas 手绘，无新依赖）
1. **js/personal-stats.js 小重构**：把 `renderPersonalStats` 中"总览数字 + scoreHistory/dailyScoreHistory"的计算段提取为 `computePersonalStatsData(playerName)`（返回 totalMatches/wins/losses/curScore/maxScore/bestRank/scoreHistory/dailyScoreHistory），`renderPersonalStats` 改为"取数 + 渲染"，行为不变——避免导出功能复制重放逻辑造成漂移。
2. **js/player-page.js**：
   - `initPlayerPage`/`reapplyPlayerPage` 在顶栏（`.player-page-top`）注入「导出图片」按钮（复用 `.btn .btn-sm` 样式，addEventListener 绑定）。
   - `exportPlayerShareCard(player)`：**纯 Canvas 手绘**战绩卡（与 `buildRankTableImageCanvas` 同款写法：读 body CSS 变量跟随主题、同款字体栈、DPR 2~3 缩放、圆角卡片）：
     - 头部：左侧「个人战绩卡」标题 + 右侧 "WFLS TT Club"；
     - 姓名 + #uid + 现役/校友徽章（`pp_status_active/alumni` 已有）+ 角色徽章；
     - 标签/荣誉 chips（最多两行）；
     - 2×3 大数字格：当前积分 / 当前排名 / 总场次 / 胜率 / 最高积分 / 最佳排名；
     - 积分走势迷你折线（dailyScoreHistory 降采样 ≤80 点，面积填充 + 首末日期）；
     - 页脚：player.html 链接 + 生成时间。
     - 下载文件名 `wfls-player-{uid}`；生成期间按钮禁用 + 转圈图标。
3. i18n（zh/en 各加）：`pp_export_btn`（导出图片 / Save Image）、`pp_card_title`（个人战绩卡 / Player Stats Card）、`pp_export_fail`（战绩卡导出失败，请重试 / Card export failed. Please try again.）。
4. player.html **不需要**引入任何新脚本。

## C. n/c/q 详情导出为图片（detail.html，html2canvas DOM 截图）
1. **detail.html**：
   - hero 内 `#detailVersion` 后加 `<div id="detailActions"></div>`；
   - 在 `js/common.js` 之前加 `<script src="https://cdnjs.cloudflare.com/ajax/libs/html2canvas/1.4.1/html2canvas.min.js" integrity="..." crossorigin="anonymous">`（实现时用 `curl | openssl dgst -sha384 -binary | base64` 计算 SRI）。
2. **js/common.js** 详情渲染区：
   - `renderDetailExportButton(type, item)`：向 `#detailActions` 注入「导出图片」按钮；`renderDetailMessage()`（错误态）里隐藏它。
   - `exportDetailAsImage()`：基于 `detailState` 构建**离屏导出节点**（fixed + left:-10000px，宽 820px，背景 `var(--bg-white)`，随当前主题）：
     - 头部：类型标签（news/competition/qa 的 i18n tag）+ 右侧 "WFLS TT Club"；
     - 标题 + 日期；
     - 正文：直接克隆 `#detailContent` 已渲染的 HTML（marked+KaTeX 成品，套 `.detail-body` 类保持排版）；
     - 配图：克隆 `#detailMedia` 里的 `<img>`（跳过视频/文件；克隆时改 `loading='eager'` 并 await 全部加载）；
     - 页脚：详情页链接 + 生成时间戳。
     - 完成后 `exportDomNodeAsImage()`，文件名 `wfls-detail-{type}-{id}`；**不包含**赛程签表（#detailDraws）与视频。
   - 挂接点：`renderDetailItem()` 末尾调用 `renderDetailExportButton()`。
3. i18n（zh/en 各加）：`detail_export_btn`（导出图片 / Save Image）、`detail_export_fail`。

## 明确不做
- 不做 JSON 导出（按你的决定，个人数据只出战绩卡图片）。
- WTT 管线（wtt_player.html 等）不加导出，后续可按同模式复制。
- personal_stats.html 列表页不加按钮（点击即跳 player.html）。
- 不动 nav/footer、index.json/search.json、排行榜现有导出。

- 无数据/内容改动 → 跑一遍 `python tools/ci_validate.py` 作回归确认即可。
