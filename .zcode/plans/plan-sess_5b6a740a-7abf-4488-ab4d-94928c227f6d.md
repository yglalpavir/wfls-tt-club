# 腾讯文档收集表:无 GitHub 同学的提交通道

## 流程设计

```
同学: 打开腾讯文档收集表链接(免账号填写) → 数据自动进在线表格
你:   在表格里人工标记「审核」列(通过/拒绝)
      文件 → 导出为 CSV → python tools/import_submissions_csv.py 导出.csv
      工具自动校验(复用现有校验逻辑)→ 追加 score-log.json → 你 ci_validate + git 提交上线
```

- 不接任何云平台、无 Action、无密钥;审核在腾讯文档里完成,入库靠本地工具,与你现有 admin.html 工作流同级。
- 现有 GitHub Issue 审核流水线**原样保留**,成为双通道之一。

## 新增文件

1. **`tools/import_submissions_csv.py`** — CSV 导入工具:
   - 编码兜底(腾讯文档导出可能是 UTF-8-BOM 或 GBK,自动探测)
   - 表头模糊匹配(日期/比赛类型/赛制/胜者/负者/总比分/逐局分数/备注/提交人,容错列名差异)
   - 日期规范化(容忍 `2026/9/12`、`2026-9-12 23:30` 等格式 → `YYYY-MM-DD`)
   - 校验逻辑直接 `import` 复用 `append_submission.py` 的 `validate_match`/`validate_bonus`(选手名、类型白名单、赛制、比分自洽全套规则,零重复实现)
   - **`--dry-run`**:只预览解析结果不写入(首次对接真实导出文件时先用它)
   - 可选 `--status-column 审核 --status-value 通过`:只导入标记通过的行
   - **去重**:已导入行的内容指纹记在 `tools/.import-state.json`(加入 .gitignore,仿照 `.ittf_creds.json` 本地凭据惯例),重复导出/重跑自动跳过
   - 结果报告:成功 N 条、跳过 M 条(逐条原因,如"选手不在册——请先在 players.json 建档后重跑");校验失败的行不会写入,可修复后重跑

2. **`.gitignore`** — 加 `tools/.import-state.json`

## 修改文件(2 处)

- **`submit.html`**:页面顶部新增「免账号提交(推荐)」卡片——大按钮直接跳转你的腾讯文档收集表链接(留 `TENCENT_FORM_URL` 常量,你建好表把链接发我或自己填);现有录入表单保留,服务 GitHub Issue 路径;「复制 JSON 发 QQ 群」继续作为第三兜底。i18n 键增补(中英)。
- **`README.md` + `AGENTS.md`**:记录三通道流程(腾讯文档/GitHub Issue/QQ 群)、收集表创建指引(题目清单可复制)与 CSV 导入操作步骤。

## 你的一次性 setup(实施完成后)

1. 腾讯文档 → 新建「收集表」→ 添加题目(我会把题目清单写进 README,直接照抄):日期(必填)/比赛类型(单选,按 event-coefficient.json 的 7 个类型)/赛制(单选 default-bo7)/胜者(必填)/负者(必填)/总比分(选填)/逐局分数(选填)/备注/你的昵称;分享设置尽量选「免登录可填」(若腾讯要求 QQ 登录,门槛也只是一键授权)
2. 把收集表链接填进 submit.html 常量
3. 之后每次入库:标记审核列 → 导出 CSV → `--dry-run` 预览 → 正式导入 → `ci_validate.py` → 提交

## 已知取舍(诚实声明)

- 腾讯文档侧没有我们的实时校验(无选手补全、无比分自洽检查),错误数据靠导入时校验兜底 + 你人工审核拦截——这正是该方案"零配置"换来的代价
- 腾讯文档导出 CSV 的具体列名/编码我无法提前验证,所以导入器做成防御式(模糊匹配+编码探测),首次对接用 `--dry-run` 确认
- 数据在腾讯文档服务器上(公开统计类信息,无敏感字段),介意的话随时可迁到 CF Workers 方案

## 验证方式

1. `node --check` / `ci_validate` / `sync_content --check` 全绿
2. 合成 CSV 夹具测试:合法行导入、非法行跳过并报告、重跑去重、`--dry-run` 不落盘、GBK 编码容错
3. 浏览器实测 submit.html 新卡片(双主题)
4. 你建好真实收集表后,导出一份真实 CSV 跑 `--dry-run` 做最终对接验证
